# Long Research Program

This is the future project design beyond the first card. It is staged so the project cannot drift into scattered experiments.

## North Star

Build a discipline for finding, testing, and retiring internal control surfaces in learned systems.

The long program should produce:

- supported mechanism cards;
- failed mechanism cards;
- reliability atlases;
- method comparisons;
- theory of intervention-valid signatures;
- eventual product primitives if the science earns them.

## Stage 0: No-Code Doctrine

Status:

- active in this rebuild.

Exit:

- clear target;
- preregistration;
- stack decision;
- prompt design;
- review rubric;
- artifact standards;
- adversarial closure.

## Stage 1: MC-001 Sycophancy Truth Conflict

Purpose:

Test whether the mechanism-card contract works on a clean, safety-relevant behavior.

Expected lesson:

- whether hidden signatures beat output/prompt baselines;
- whether activation interventions reduce wrong-hint compliance without generic refusal;
- whether simple methods are enough.

Decision after stage:

- if supported: deepen mechanism resolution and replicate;
- if diagnostic-only: study why prediction did not imply control;
- if failed-controls: choose a cleaner target or revise method standard.

## Stage 2: MC-002 Hallucination Gate

Only start after MC-001 is supported, failed cleanly, or retired.

Question:

Can hidden-state signatures separate answer knowledge, uncertainty, and confabulation better than output confidence?

Why second:

Hallucination has higher market value but messier labels.

Required improvements over MC-001:

- entity familiarity controls;
- retrieval availability controls;
- known versus unknown item splits;
- uncertainty calibration;
- refusal side-effect tracking.

## Stage 3: MC-003 Evaluation Awareness

Question:

Can hidden signatures detect benchmark/test-awareness before the model verbalizes it?

Why third:

High strategic value, high confounding risk.

Required controls:

- benchmark formatting controls;
- ordinary user task controls;
- hidden metadata removal;
- synthetic marker tests;
- intervention tests that do not merely damage performance.

## Stage 4: Reliability Atlas Across Models

Question:

Which mechanism cards survive across:

- base versus instruction tuned;
- model scale;
- model family;
- language;
- prompt style;
- task family;
- context length.

Output:

Not a universal claim. A reliability atlas.

## Stage 5: Mechanism Diffing

Question:

Can internal differences between model versions predict behavior differences?

Targets:

- base to instruction-tuned;
- pre-safety to post-safety;
- before and after finetuning;
- small to larger family member.

Value:

This is directly useful to model developers.

## Stage 6: Mechanism-Carrying Training

Question:

Can a validated mechanism be preserved, weakened, or strengthened during finetuning or distillation?

Experiments:

- output-only distillation;
- internal-feature-aware distillation;
- safety finetuning with mechanism tracking;
- training-health monitor for mechanism emergence.

Possible outcome:

Mechanisms may be local to model state and not transferable. That would be important.

## Stage 7: Intervention Theory

Question:

Can we predict which signatures will become controllable before running expensive interventions?

Needed data:

- successful cards;
- failed predictive signatures;
- failed interventions;
- side-effect maps;
- method-comparison results.

This is where the math program earns its keep.

## Stage 8: Cross-System Universality Gate

Question:

Do any mechanism classes survive outside ordinary transformer LLMs?

Candidates:

- vision-language models;
- code agents;
- state-space or recurrent language models;
- world models;
- eventually biological data.

Rule:

Do not run this as theater. Cross-system work only begins after a mechanism is strong in LLMs.

## Stage 9: Product Primitive

Only after multiple cards.

Candidates:

- mechanism-card workbench;
- hidden-state monitor;
- intervention sandbox;
- model-diff report;
- reliability atlas registry.

Decision gate:

Build product only when hidden-state methods beat simpler deployed alternatives.

## Portfolio Kill Rule

After three serious cards:

- if none beat output/prompt/trace baselines, pivot away from control-surface product claims;
- if signatures predict but do not control, focus on diagnostics;
- if controls work but explanations are weak, focus on intervention safety and side effects;
- if controls and explanations work, expand the mechanism-card factory.
